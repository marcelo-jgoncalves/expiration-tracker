## Achado headline desta rodada: suíte completa está VERMELHA agora

`npm test` (execução completa, 2026-09-07): **Test Files 1 failed | 235 passed (236)**, **Tests 1 failed | 2624 passed (2625)**.

```
FAIL test/architecture/system-mutation-allowlist.test.ts > ... > control: a fixture file
constructing every real allowlisted kind ... typechecks cleanly
AssertionError: unexpected typecheck failure on a fixture using only real allowlisted kinds:
error TS6053: File '.../src/modules/expiration/application/__tenant_fence_boundary_test_fixtures__/bypass-transact/direct-transact.ts' not found.
```

Este é um teste de ARQUITETURA (`test/architecture/system-mutation-allowlist.test.ts`) que planta um fixture real sob `src/` e invoca `tsc` real como subprocesso para provar que a união `SystemMutationOperation` é fechada em tempo de compilação — mesmo mecanismo de `tenant-fence-boundary.test.ts`. O erro cita um arquivo fixture de OUTRO arquivo de teste de arquitetura (`__tenant_fence_boundary_test_fixtures__/bypass-transact/direct-transact.ts`), que não existe na árvore no momento da checagem (`find` confirma: nenhum fixture residual presente após a execução). `vitest.config.ts` já documenta esta classe exata de problema (`fileParallelism: false`, comentário explícito sobre corrida entre dois arquivos de teste de arquitetura que plantam/removem fixtures sob `src/` concorrentemente) — mas o próprio comentário prova que essa mitigação foi aplicada especificamente para ESTE padrão e, mesmo assim, uma corrida real ocorreu nesta execução: o `tsc` de um teste (`system-mutation-allowlist`) leu um `tsconfig.json` cujo padrão `include: "src"` capturou um arquivo fixture de OUTRO teste de arquitetura (`tenant-fence-boundary`) no instante exato entre esse fixture ser plantado e removido pelo dono dele. `fileParallelism: false` serializa arquivos de teste, mas não impede que dois testes DENTRO do mesmo arquivo, ou hooks `beforeAll`/`afterEach` de arquivos adjacentes na fila, se sobreponham na janela de um `tsc` filho que lê o disco de forma assíncrona.

**Rerun isolado do arquivo falho, sozinho**: pendente de confirmação nesta sessão (comando em execução) — a hipótese de flakiness/corrida (não regressão de código de produção) é fortemente sustentada pelo próprio comentário do `vitest.config.ts`, pela ausência de qualquer fixture residual pós-execução, e pelo fato de que os testes de arquitetura afetados envolvem literalmente dois arquivos diferentes cujos nomes aparecem cruzados no erro (o teste que falhou é de `system-mutation-allowlist`, o arquivo que faltou é de `tenant-fence-boundary`).

**Classificação**: Nível 3-4 (`change-risk-scale.md`) — não é correção mecânica de uma linha; exige entender por que a serialização por arquivo (`fileParallelism: false`) não é suficiente para isolar dois `tsc` filhos que compartilham o mesmo `tsconfig.json`/`include` de árvore inteira, e desenhar um isolamento mais forte (ex.: `tsconfig` dedicado por fixture, diretório de fixture fora do `include` padrão, ou lock explícito entre os dois arquivos de teste de arquitetura). **PENDENTE — não corrigido nesta sessão**, registrado para decisão futura, não decidido unilateralmente aqui.
