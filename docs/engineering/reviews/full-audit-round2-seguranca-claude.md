# Full audit round2 — Eixo Segurança da Informação e AppSec — Proposta Claude (nota cega)

Protocolo `AGENTS.md` §4, nota cega. Critérios/pesos: `docs/engineering/joint-review-criteria.md` §"Eixo: Segurança da Informação e AppSec" (10 critérios, convergido 2026-08-19). Baseline: `docs/engineering/reviews/full-audit-round1-seguranca-summary.md` (Round1 fechou sub-9.0 honesto: Claude 7.895/Codex 7.315). Desde então o sistema cresceu enormemente (document-archive completo, guest access, webhook WhatsApp, activity log, dossier export) — esta rodada reavalia o eixo inteiro contra a superfície real de hoje, não só as correções pontuais de Round1.

## Metodologia

Evidência coletada nesta sessão (2026-09-07): leitura de `authorization.ts` (RBAC), `infra/modules/dynamo-table/main.tf` (IAM), `whatsapp-webhook-processor.ts`/`whatsapp-webhook-handler.ts` (assinatura HMAC), `document-archive-guest-*` (D-146, pepper isolation), `decisions-log.md` (D-146/D-217/D-225/D-231), `npm audit` (raiz + frontend), `npm run check-boundaries`, grep por `eval(`/`child_process`/`console.*` em `src/`.

IAM nativo não oferece primitiva de "SK prefix" via os data sources usados aqui sem reescrever manualmente cada policy — resolver isso é trabalho de design (nível 5-6), não uma correção pontual. |

## Achados novos desta rodada (não presentes no Round1)

1. **[Nível 2, mecânico]** Drift de `docs/engineering/exceptions.md` EX-001: registrado com "9 vulnerabilidades (2 critical, 5 high, 2 moderate)", mas `npm audit` real hoje (raiz) reporta **11** (2 critical, 5 high, **4** moderate) — 2 moderate novas não cobertas por nenhuma exceção: `exceljs@4.4.0` (dependência de PRODUÇÃO, D-217 dossier XLSX) → `uuid@8.3.2` (missing buffer bounds check, GHSA moderate). Não bloqueia CI (`--audit-level=high`), mas é uma vulnerabilidade real de produção sem registro formal — corrigido nesta sessão (ver abaixo).
2. **[Nível 5-6, PENDENTE — decisão de design]** Critério 2 (IAM least-privilege) não regrediu, mas o blast radius do grant amplo aumentou proporcionalmente ao número de módulos tenant-facing novos desde Round1 (document-archive inteiro, activity, dossier). Continua sem correção — registrar explicitamente que esta é a MESMA lacuna de Round1, agora com escopo maior, não uma lacuna nova a decidir do zero.
3. **[Nível 3, PENDENTE — verificação]** Não confirmado se `TenantQuotaService` cobre as rotas de negócio adicionadas desde Round1 (`/document-archive/*`, `/activity`, `/document-archive/series*`). Se não cobrir, é uma regressão exata do bug que Round1 já corrigiu uma vez em outras rotas.
4. **[Nível 4, PENDENTE — verificação]** Não confirmado nesta sessão se todos os novos call sites de `authorize()` (RBAC `docarchive:*`) alimentam `security-audit.ts` de forma consistente para o critério 7 (trilha de autorização negada).
